NO CAMERA, PHASES 5–7 — photos taken by hand, classified, and on the web
================================================================================
Written 2026-11-16. Branch: feat/no-camera. Waiting on: Reagan's classifier.

THE DECISION (2026-11-15, docs/features/architecture.txt, DECISIONS): the AI
deck is off the drone, so there is no camera. A person takes photos of the
equipment and uploads them in the desktop app; the image classifier judges
each photo on the laptop; photos and verdicts go up to the website. Flights
are processed only after their data has arrived — no live verdicts.

BEFORE PHASE 5 — WHAT REAGAN HANDS OVER (the gate; expected in a few days)
--------------------------------------------------------------------------------
Phase 5 starts when these are in hand. Reagan agreed (2026-11-15) that we port
and adapt the stage for photos; he finishes the model.

  1. A MODEL TRAINED ON PHOTOS TAKEN BY HAND, not drone frames. The current
     ml/image-classifier/ (origin/feat/image-model-stage) shrinks every photo
     to the drone camera's 324 × 244 grayscale and inpaints a viewer's
     crosshair. Both were for the camera and both go: train on what a phone
     or camera gives (colour, any size). The dataset stays a manifest
     (manifests/images.csv) — photos never committed — split BY SESSION, with
     results on a held-out session.
  2. THE INPUT CONTRACT, WRITTEN ONCE, in ml/image-classifier/preprocess.py
     as to_model_input(): colour or grayscale, how a photo is fitted to the
     input (squash, crop or pad), the size, the normalisation. The agent
     copies it exactly and a test holds the two together, so it must be
     unambiguous — including what happens to a portrait photo and to EXIF
     rotation.
  3. THE ONNX FILE, under 20 MB, run by ONNX Runtime on the CPU. Output as
     today, 1 × 2 logits [normal, faulty], unless he says otherwise.
  4. ITS MODELS.json ENTRY: name, version, file, sha256, source (how it was
     trained, from what weights), licence, input, output, threshold
     (p_faulty at or above it is "faulty"). The format is the one in
     docs/handoffs/sprint-1/done/dpp-contract.txt, MODEL FILES.
  5. WHAT "FAULTY" MEANS for this model — a gauge's needle in its high zone,
     visible damage, or both (classify.txt on his branch; PROVISIONAL until
     story 6.1) — and WHETHER THE GAUGE READERS (pressure_gauge.py,
     status_gauge.py) are part of the verdict. On his branch they are not
     called by anything. If they are wanted in Phase 5, say what a photo's
     verdict does with a reading.
  6. WHERE: push it to origin/feat/image-model-stage (or a new branch). No
     rebase is needed — that branch is on the old cropwatcher/ paths, 70
     commits behind main; Phase 5 ports the files onto dronedeck/.

  If it is late: Phase 5 could be built with the model slot empty — every
  photo reads "unknown — no image model yet", exactly as the stage was
  designed — and the model dropped in by a MODELS.json entry. Decided
  2026-11-16 NOT to do that: Phase 5 waits for the model.

PHASE 5 — PHOTOS IN THE DESKTOP APP, CLASSIFIED ON THE LAPTOP
--------------------------------------------------------------------------------
UPLOAD (desktop: Sessions page)
  - Each session gets "Add photos" (JPEG, PNG; several at once), for an
    ended or an open session. Each photo can be tagged with one of that
    session's inspection points (from its missions), or left untagged — the
    tag is what a later task builds on (below).
  - The gallery: CaptureGallery.tsx was deleted in Phase 3 (it only read
    camera frames). Copy-adapt it from git (`git show 6dfe230^:desktop/src/
    components/CaptureGallery.tsx`) with /copy-adapt, not from scratch.

STORE (agent)
  - POST /history/sessions/{id}/photos, multipart, token-gated like every
    command. Checks: the session exists on this laptop; JPEG or PNG by its
    bytes, not its name; a size cap; a safe file name (never the uploaded
    one as a path).
  - On disk: sessions/<id>/photos/<seq>.<ext> and an index, photos.csv
    (seq, original name, point_id, sha256, uploaded_at, size). Written
    before anything is uploaded (CLAUDE.md invariant 6).
  - Routes to list a session's photos and serve one (the window's CSP
    already allows images from 127.0.0.1:8765), and to set or clear a
    photo's point.
  - An audit event per upload (audit.py).
  - NEW DEPENDENCY: python-multipart (FastAPI needs it for an upload; not in
    pyproject.toml today). It must also be in the frozen agent: add it to
    the self-test list (cli.py SELFTEST_MODULES) and check build_sidecar.

CLASSIFY (agent, after arrival — never in flight)
  - Port Reagan's stage onto dronedeck/: image.py (the ONNX loader, the
    sha256 check, "unknown" with a reason when anything fails) and, if
    wanted, the gauge readers. reticle.py is not ported.
  - It is NOT a stage of the flight pipeline (contract v3 is sensors only).
    A new job kind, "photos", in processing.py: queued when photos are
    added, run in a child process like the others, one session at a time.
    Adding a photo never re-runs a flight's sensor analysis.
  - Output: results/sessions/<id>/photos.json — per photo: label, p_faulty,
    model "<name>@<version>", reason when unknown, classified_at.
  - NEW DEPENDENCY: onnxruntime. Into the frozen agent too; measure its size
    (OpenCV took it 43 → 86 MB, dpp-contract.txt rule 11).
  - OPENCV IS NOT IN THE FROZEN AGENT. opencv-python-headless is still in
    pyproject.toml, so the venv has it, but since the camera code went no
    module imports cv2, so PyInstaller leaves it out (the agent is 44 MB).
    "cv2" came off cli.py SELFTEST_MODULES on 2026-11-18 for that reason: the
    build failed verifying it. If the classifier uses OpenCV, put "cv2" back
    in SELFTEST_MODULES in the same change, or the installed app breaks the
    first time it handles a photo while every test still passes.
  - A photo's verdict never makes or changes a sensor finding: the
    telemetry stays the evidence (the owner, 2026-10-09).

SHOW (desktop)
  - Each photo's verdict in the session's gallery, in words and never by
    colour alone (design/layout.txt), with the model that judged it.

  agent ruff, mypy, pytest (upload: a refused file, a bad id, a wrong type;
